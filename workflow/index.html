Model derivation

The nationwide model lhm_coupled is built in stages, which the DVC pipeline runs in order. Each authority starts from its own kind of data, so there are three routes to a model that are merged at the end:

  • The main water system of Rijkswaterstaat.
  • The gravity controlled models of 11 water authorities, which mostly drain freely (vrij afwaterend), lumped from their watercourses.
  • The level controlled models of 10 water authorities, which keep target levels in their polders (peilbeheerst), built from the crossings of their watercourses with the boundaries of their level areas.

The stages

Stage What it does See
bathymetry, hws_demand, hws_transient The model of the main water system. Main water system
hydamo, lumped Lump the watercourses and structures into an input model. Lumping
parameterized, bergend, dynamic Fix and parameterize the model, add control, storage basins and forcing. Gravity controlled
postprocessed, crossings, shortest_paths, boezemmodel Make an input model from the deliveries. Level controlled
feedback, profiles, forcing Process the feedback of the water board, add profiles, control and forcing. Level controlled, Profile generation
rwzi The wastewater treatment plants, as a model to merge. Forcing
peilbeheer The summer and winter levels of the level areas. Summer and winter levels
samenvoegen, koppelen Merge all models, and connect them where they meet. Coupling
run_lhm_coupled, validate_lhm_coupled Run the model and check its results. Testing
export_webmap Export the run for the model viewer. Model viewer
hws_plus Cut the main water system out of the run, with its exchanges as boundaries. HWS plus

Where the data is

Everything is under data, with a folder per authority, named as in ribasim_nl.aquo, and Basisgegevens for national data:

Folder Content
<authority>/aangeleverd Data as delivered by the authority
<authority>/verwerkt Processed data, including hand-made edits such as model_edits.gpkg
<authority>/modellen The models of each stage, such as <authority>_dynamic_model
Rijkswaterstaat/modellen Also the merged lhm_parts and coupled lhm_coupled models
Rijkswaterstaat/runs/lhm_coupled The latest run of the coupled model, with its results

Get data explains how to download these.

Node IDs

Scripts and edit files refer to nodes by their ID, in the model of the authority. Merging keeps these unique by prefixing them with the waterbeheercode of the authority, see ribasim_nl.aquo:

\[\text{node ID in the coupled model} = \text{waterbeheercode} \times 100\,000 + \text{node ID in the regional model}\]

So 203892 is node 3892 of Wetterskip Fryslân, with code 2, and 8009406 is node 9406 of Rijkswaterstaat, with code 80. The model viewer shows the same IDs. Fix a problem in the stages of the authority where possible, rather than in the coupling, so that the regional model and the nationwide model stay alike.

The IDs must stay the same on every run, or all these references break, see Reproducing models.

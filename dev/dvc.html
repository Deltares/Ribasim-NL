DVC (Data Version Control)

We use DVC to version-control large data files (models, input datasets) without storing them in Git. Git only stores small fingerprints of the data, in dvc.lock and .dvc files; the data itself lives on MinIO storage.

DVC also describes how the data is made: the pipeline in dvc.yaml is a list of stages, each a Python script with its input and output files. Most stages build the model of one water authority, and later stages combine them into the nationwide model.

In short

You only need a few commands, always run through Pixi so your access key from .env is used (see Add your access key):

Goal Command
Download a file or folder pixi run dvc pull <path>
Download the inputs of a stage, e.g. rwzi pixi run dvc pull rwzi --with-deps
Rerun a stage after changing its script pixi run dvc repro --pull rwzi
See which stages are out of date pixi run dvc status

The sections below explain these in more detail.

Note

Existing clones may still have remote credentials in .dvc/config.local. Remove those credential fields after migrating .env from MINIO_ACCESS_KEY and MINIO_SECRET_KEY to AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY.

Pull data

Prefer pulling only the data needed for the stage you are working on. To fetch a stage and its dependencies without reproducing it, use dvc pull:

pixi run dvc pull rwzi --with-deps

To fetch the cached coupled LHM model (koppelen) and its results (run_lhm_coupled) without pulling their dependencies:

pixi run dvc pull koppelen run_lhm_coupled

The results in data/Rijkswaterstaat/runs/lhm_coupled read their input from data/Rijkswaterstaat/modellen/lhm_coupled, so pull both to open lhm_coupled.toml with results. Do not add --with-deps here; that also pulls all regional models upstream.

The final cached outputs for (for example) Aa en Maas and Amstel, Gooi en Vecht can likewise be pulled directly:

pixi run dvc pull data/AaenMaas/modellen/AaenMaas_dynamic_model/
pixi run dvc pull data/AmstelGooienVecht/modellen/AmstelGooienVecht_forcing/

Only pull all tracked data when you have enough disk space (currently ~100GB), time, and just want all data local:

pixi run dvc pull

If you have local changes that you want to overwrite, add --force.

Remotes

The MinIO remote is configured in .dvc/config:

Remote URL Purpose
minio (default) s3://ribasim-nl/dvc Primary DVC cache on MinIO

Pipeline

The DVC pipeline is defined in dvc.yaml. Each stage depends on its scripts, its input data, and the src/ribasim_nl/ribasim_nl package as a whole. Every stage imports most of this package, so a change to it marks all stages as changed. That sometimes reruns a stage that did not need it, but never skips one whose code changed.

Reproduce stages

During development, reproduce only the stage you are working on. The --pull option asks DVC to fetch missing dependencies before running the stage with dvc repro:

pixi run dvc repro --pull rwzi

Without --pull, dvc repro only uses data already present in the workspace or local DVC cache. Other useful options are --force to run a stage even when DVC considers it unchanged and --single-item to run only the named stage without reproducing its upstream dependencies.

Warning

A full pixi run dvc repro runs all stages one by one and takes several days. Run full reproductions in parallel instead, on a workstation with pixi run repro-local, see Running locally, or on the SLURM cluster with repro.sh, see Running on SLURM.

Pushing changes

After producing new outputs (running pipeline stages or adding new data), push to the remote:

pixi run dvc push

Do this before pushing the updated dvc.lock file to Git, so the data hashes referenced therein are available to everyone.

Most MinIO access keys handed out are read-only. Reach out if you need help uploading data. In general we update all results after a full cluster run.

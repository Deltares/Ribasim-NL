webmap_publish

webmap_publish

Publish the export_webmap output to MinIO for the model viewer on the documentation site.

pixi run publish-webmap            # the model of the pull request of this branch, compared with its base
pixi run publish-webmap --pr 123   # the model of the working tree as that pull request
pixi run publish-webmap --main     # only the model of origin/main
pixi run publish-webmap --commit REV [--base REV]  # the model of a commit, compared with another commit

Everything is uploaded below the anonymously readable doc-image/webmap/ prefix:

  • files/<hash>.<ext>: the exported files, named by their content hash, so files that did not change are uploaded once and shared by all models.
  • lhm_coupled/snapshots/<md5>/manifest.json: the manifest of an export, with the paths of the files in files/. The snapshot is named by the DVC hash of the export_webmap output in dvc.lock, which is how the viewer finds the model of main: it reads dvc.lock from GitHub.
  • lhm_coupled/main.json: the snapshot of the latest published main, for when the snapshot of the current main is not published.
  • lhm_coupled/diffs/<base md5>-<head md5>.json: the differences between two snapshots, see ribasim_nl.webmap_diff.
  • lhm_coupled/prs/<number>.json: the snapshots and differences of a pull request, which the viewer shows for ?pr=<number>. A pull request is compared with main, or in a stack of pull requests with the pull request of its base branch, so it only shows its own changes. That pull request must be published first.

The viewer finds the model of any commit on GitHub, for ?commit=<commit>, by the snapshot in its dvc.lock, and compares it with that of another commit, for ?base=<commit>&commit=<commit>, if their differences are published. It pins the link to the latest main to its commit, so a copied link keeps showing the same model.

DVC does not cache the export_webmap output, so this is the only copy that is kept. The export of another commit, to compare with, is downloaded from its published snapshot. If it is not published, the model is exported again from its run, which DVC does keep.

This needs the following environment variables to be set in .env (Deltares only): AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY They need to have write permission. A pull request is found and commented on with the GitHub CLI gh.
